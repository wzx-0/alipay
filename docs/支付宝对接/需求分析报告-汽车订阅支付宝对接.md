## 一、结论(先说结论)

| 项 | 结论 |
|---|---|
| 业务本质 | 商家在支付宝小程序内开展"汽车订阅"(以租代购/按月订阅)业务,借助支付宝**租赁交易组件 + 租赁快捷下单插件**打通信息流、订单流、资金流,通过**芝麻免押(预授权)** + **代扣**完成签约扣款 |
| 需对接支付宝接口 | 服务端 API 约 **15 个**、异步通知 **4 类**、小程序前端能力 **4 项**(插件 + 3 个 JSAPI) |
| 后端开发核心 | 8 大模块:商品映射、订单(含状态机)、签约免押、风控审核、支付扣款、履约、售后、续订/买断 + 统一异步通知网关与代扣定时调度 |
| 硬性前置 | biz_identity=CAR_SUBSCRIPTION 需**白名单**(APPID+PID 找支付宝业务开通);企业类目 B0051;商品须先提报商品库;产品清单需芝麻运营开通 |
| 我方责任边界 | 插件负责商品详情/下单页/免押受理台唤起,**后端只对接 openapi 服务端接口 + 接收异步通知**,自建订单详情页、私域自建商品页 |

## 二、业务流程与订单状态机

### 2.1 状态机映射(需求文档 §2.3)

| 支付宝订单状态 | 业务含义 | 触达该状态的动作/接口 |
|---|---|---|
| 申请中(CREATED) | 用户下单,尚未签约 | 用户插件内提交订单 → `order.create` |
| SIGNED | 完成签约(免押预授权 + 代扣协议) | 插件自动唤起受理台,或 `order.sign` 补偿唤起;签约成功自动变更 |
| APPROVED | 商家风控审核通过,待发货 | `fulfillment.approve`(拒绝则 `order.close`) |
| DELIVERED | 商家已发货(签订合同后交车) | `fulfillment.send`,type=MERCHANT_DELIVERY_SEND |
| RECEIVED | 用户确认收车 → 订阅中 | `fulfillment.receive`,type=MERCHANT_DELIVERY_RECEIVED |
| RETURN_DELIVERED | 用户完成还车 | `fulfillment.send`,type=USER_DELIVERY_SEND |
| RETURN_RECEIVED | 商家确认收到归还车辆(押金未解冻) | `fulfillment.receive`,type=USER_DELIVERY_RECEIVED |
| 已完结(FINISHED) | 归还/买断/续租完结,**自动解冻押金、解除代扣协议** | `fulfillment.finish`:USER_RETURNED / USER_RETURNED_IN_ADVANCE / OTHER |

### 2.2 主链路(公域,插件版)

```
用户浏览插件商品页 → 提交订单
  ├─ 小程序 app.ts 回调 setRentCarOrderSubmitCallback
  │    ① my.checkBeforeAddOrder(前置校验取 sourceId)
  │    ② 商家后端 → alipay.commerce.rent.order.create 创业务单
  │    ③ 返回 orderId / outOrderId / path
  ├─ 插件自动唤起芝麻免押受理台(签约:预授权冻结 + 代扣协议)
  │    └─ 用户退出受理台 → order.sign 重新唤起
  ├─ 商家后端 → risk.consult 查综合风险(T1~T10) → 人工/自动审核
  │    ├─ 通过 → fulfillment.approve
  │    └─ 拒绝 → order.close
  ├─ 签订订阅合同 → fulfillment.send 发货 → 用户确认收车 fulfillment.receive
  ├─ 订阅中:按 rent_plan_info 的 plan_pay_time 逐期发起 order.pay(RENT_DEDUCT 代扣)
  ├─ 到期还车:send(USER_DELIVERY_SEND) → receive(USER_DELIVERY_RECEIVED) 验收
  │    ├─ 无损 → fulfillment.finish(USER_RETURNED)完结,自动解冻+解约
  │    └─ 有损 → aftersale.create(COMPENSATION)收赔付金后再完结
  └─ 续订 RELET / 到期买断 BUYOUT → 再次 order.create 创新单
```

## 三、需要对接的支付宝接口清单

### 3.1 服务端 OpenAPI(商家后端 → 支付宝)

| # | 接口 | 用途 | 关键参数/要点 | 文档步骤 |
|---|---|---|---|---|
| 1 | `alipay.commerce.rent.order.create` | 租赁订单创建 | order_type=RENT/RELET/BUYOUT;biz_identity 固定 **CAR_SUBSCRIPTION**;rent_plan_info.installments(≤36期,首期外金额一致,第2期起 plan_pay_time 后才能代扣);price_info(deposit_price>0 作免押冻结额;order_price=运费+增值服务费+Σ每期金额);item_infos(item_type 固定 **CAR_ITEM**,仅1项,优先传商品库 out_item_id/out_sku_id);rent_sign_info(credit_info 芝麻服务ID、freeze_notify_url **必传**、sign_scene=RENT_DEDUCT);delivery_type 固定 **SELFPICK**;trade_app_id 异主体必传;续订传 relet_info;买断传 buyout_info.origin_order_id | 步骤2/11/12 |
| 2 | `alipay.commerce.rent.order.query` | 订单/账单查询 | 查询租赁订单信息与账单,用于对账、状态核对 | 步骤2-其他 |
| 3 | `alipay.commerce.rent.order.sign` | 租赁订单签约 | 插件受理台被用户关闭后,在自有订单详情页再次唤起;rent_sign_info 与创单保持一致;返回 sign_str 由前端唤起受理台 | 步骤3 |
| 4 | `alipay.commerce.rent.risk.consult` | 租赁风险咨询 | consult_risk_types=COMPREHENSIVE_RISK,返回 T1~T10;映射:T1-T4 通过 / T5-T6 人工综合判断 / T7-T10 拒绝(租安盾-汽车订阅定制版) | 步骤4 |
| 5 | `alipay.commerce.rent.order.fulfillment.approve` | 商家审核通过 | 推进 SIGNED→APPROVED;传 order_id/out_order_id/user_id/open_id | 步骤4 |
| 6 | `alipay.commerce.rent.order.pay` | 订单支付(每期订阅金) | pay_method=RENT_DEDUCT 代扣/PRE_AUTH 预授权转支付/JSAPI 主动支付;pay_items 按 type=RENT+installment_no 逐期支付;pay_notify_url、pay_timeout_express;受《租赁行业交易管理规范》管控 | 步骤5 |
| 7 | `alipay.trade.refund` | 统一收单退款 | 取消订单退已支付费项(取消原因商家担责时=全额,用户原因≤已支付);物损赔付扣款亦可基于预授权 | 步骤5/9 |
| 8 | `alipay.commerce.rent.order.fulfillment.send` | 发货/用户寄回同步 | type=MERCHANT_DELIVERY_SEND / USER_DELIVERY_SEND | 步骤6 |
| 9 | `alipay.commerce.rent.order.fulfillment.receive` | 确认收货 | type=MERCHANT_DELIVERY_RECEIVED / USER_DELIVERY_RECEIVED;注意 RETURN_RECEIVED 时**不自动解冻押金** | 步骤7 |
| 10 | `alipay.commerce.rent.order.fulfillment.finish` | 订单归还完结 | status=USER_RETURNED 到期归还 / USER_RETURNED_IN_ADVANCE 提前归还 / OTHER(续租无残值等);完结后**自动解冻预授权+解除代扣协议**,之后不可再发起支付 | 步骤8 |
| 11 | `alipay.commerce.rent.order.modify` | 修改租赁起止时间 | type=RENT_PLAN_TIME,同步改 installments 的 plan_pay_time 与 rent_start/end_time(如交付日变化) | 步骤10 |
| 12 | `alipay.commerce.rent.order.pay.sync` | 端外支付同步 | 微信/线下转账等非支付宝收款后同步已支付费项,pay_channel=OTHER | 步骤13 |
| 13 | `alipay.commerce.rent.order.aftersale.create` | 售后单创建 | aftersale_type=ORDER_CANCEL 取消/COMPENSATION 赔付;reason_code(物损 ITEM_DAMAGED 等);赔付类传 pay_items(type=INDEMNITY 赔付金) | 步骤9 |
| 14 | `alipay.commerce.rent.order.aftersale.confirm` | 售后商户处理 | 私域仅用终态:USER_CANCEL_APPLY(用户取消申请)/AFTERSALE_FINISH(售后完结) | 步骤9 |
| 15 | `alipay.commerce.rent.order.close` | 订单关闭 | 仅用户确认收货前可关;**关单前所有已支付费项须全额退款完成**;未签约订单 24h 超时自动关单 | 步骤14 |

补充(视需要):`alipay.open.app.item.create` 小程序商品创建(商品提报进商品库,插件必需);获取会员信息(实名认证,需运营开通)。

### 3.2 支付宝 → 商家的异步通知(需实现接收端点)

| # | 通知 | 触发时机 | 后端动作 |
|---|---|---|---|
| 1 | 预授权冻结结果通知(freeze_notify_url,创单时传入) | 用户完成免押签约、预授权冻结成功 | 更新本地签约状态(待审核),触发风控流程 |
| 2 | 支付结果通知(pay_notify_url,支付时传入) | 每期订阅金代扣/主动支付完成 | 更新账单期次支付状态,幂等入库,验签 |
| 3 | `alipay.commerce.rent.order.aftersale.notify` 消息(msg_method) | 售后单创建/状态变化(source_type 私域仅 MERCHANT) | 同步售后单状态,驱动售后处理流程 |
| 4 | `alipay.commerce.rent.order.changed` 订单变更消息(官方 API 列表,notify_type=STATUS_CHANGE) | 订单状态变更 | 对账兜底,校正本地状态机 |

### 3.3 小程序前端能力(插件/JSAPI,前端开发配合项)

| # | 能力 | 说明 |
|---|---|---|
| 1 | 插件 `goodsDetailPlugin`(provider 2021003177653028) | app.json 声明;提供商品详情页、下单页;跳转 `plugin://goodsDetailPlugin/rentCarOrder?appId&outItemId&outSkuId&quantity&duration&rentDeliveryType=SELFPICK` |
| 2 | `setRentCarOrderSubmitCallback` | app.ts 注册"提交订单"回调,内部走后端创单并返回 orderId/outOrderId/path |
| 3 | `my.checkBeforeAddOrder` | 下单前置判断,获取 sourceId |
| 4 | `my.tradePay` | JSAPI 支付(主动支付/买断)凭 trade_no 唤起收银台 |

## 四、后端开发内容(模块拆解)

### M1 商品与商品库
- 商品提报同步:`alipay.open.app.item.create` 对接商品库,维护本地商品 ↔ out_item_id/out_sku_id 映射;
- 插件展示要素保障:名称、封面主图、价格、规格、租期套餐、详情长图(汽车订阅提报按官方 SOP)。

### M2 订单模块(含状态机)
- 创单服务:接收小程序插件回调(透传 itemInfo/orderInfo/stagePayPlan/rentInfo/merchantExtInfo)→ `order.create`;
- 订单类型:RENT 首订 / RELET 续订 / BUYOUT 买断;
- 本地订单表 + 状态机(对照 §2.1 双向映射),`order.query` 定时对账 + `order.changed` 消息兜底;
- 关单:`order.close`(确认收货前),关单前置校验"已支付费项已全额退款";
- 租期变更:`order.modify`(RENT_PLAN_TIME,如实际交付日与计划不一致时调整起止时间与扣款计划)。

### M3 签约与芝麻免押
- 创单时组装 rent_sign_info:credit_info(zm_service_id/category_id 向 BD 获取)、freeze_notify_url(必传)、rent_deduct_info.sign_scene=RENT_DEDUCT;
- 冻结通知接收 → 更新签约状态;
- 受理台退出补偿:`order.sign` 返回 sign_str 交前端二次唤起;
- 私域差异:预授权类目传 **DEPOSIT_CAR_LEASING_PRI**,芝麻分门槛 650。

### M4 风控审核
- 签约完成后调用 `risk.consult`(COMPREHENSIVE_RISK)取 T1~T10 等级;
- 审核策略:T1-T4 自动通过 → approve;T5-T6 转人工;T7-T10 拒绝 → 售后取消/关单;
- 审核操作留痕(本地审核单表)。

### M5 支付与扣款(资金核心)
- 代扣调度:定时任务扫描账单期次,到达 plan_pay_time 后发起 `order.pay`(RENT_DEDUCT),pay_items 带 installment_no;遵循《租赁行业交易管理规范》扣款规则与频次限制;
- JSAPI 主动支付:创建支付单得 trade_no → 前端 my.tradePay;
- 预授权转支付(PRE_AUTH):押金转实扣场景(如物损赔付);
- 支付通知接收:验签、幂等、更新期次状态;
- 端外收款同步:`pay.sync`(pay_channel=OTHER);
- 退款:`alipay.trade.refund` 按费项退款(取消订单时)。

### M6 履约模块
- 发货/交车:fulfillment.send(MERCHANT_DELIVERY_SEND)——以**签署订阅合同**为发货前提;
- 收车确认:receive(MERCHANT_DELIVERY_RECEIVED);
- 还车:send(USER_DELIVERY_SEND) → 验收 → receive(USER_DELIVERY_RECEIVED)(此时押金未解冻);
- 完结:finish(USER_RETURNED / USER_RETURNED_IN_ADVANCE / OTHER),完结自动解冻押金、解除代扣。

### M7 售后模块
- 售后单管理:aftersale.create(取消订单/赔付)+ aftersale.confirm(终态同步);
- 售后通知接收:aftersale.notify;
- 赔付金/违约金收取:**必须在订单完结前**发起;
- 取消订单联动退款与关单。

### M8 续订与买断
- 续订:创 RELET 单,relet_info 传原订阅单号(再次续订传上一次续订单号);免押"续租必过";无需审核发货,原单租期结束次日自动推进确认收货,原单租金付完自动完结;
- 买断:创 BUYOUT 单,buyout_info.origin_order_id 传原单;平台自动发起 JSAPI,商家取 trade_no 调前端收银台;支付成功原单自动完结。

### 横切:统一通知网关 + 基础设施
- 异步通知统一接入层:验签(RSA2)、notify_id 幂等去重、biz_content 解析、失败重试 ACK 规范;
- openapi 客户端:签名、app_auth_token(异主体/服务商代调用)、错误码统一处理与重试;
- 配置:应用公私钥、网关地址、各 notify_url 常量化。

## 七、遗留确认项(开工前找支付宝/业务方确认)

1. CAR_SUBSCRIPTION 白名单(APPID+PID)申请进度;
2. zm_service_id、category_id 由 BD 提供;
3. 异主体:下单 appid 与收单 appid 是否一致(决定 trade_app_id);
4. 是否涉及二级商户/直付通(决定 sub_merchant);
5. 芝麻运营:产品清单开通、私域信用服务升级、会员信息接口权限;
6. 扣款规则细节以《租赁行业交易管理规范》(rulecenter docId=323300234)为准,需结合代扣频次/时段限制设计调度策略。
