# 汽车订阅支付宝对接 — 开发执行手册（第一阶段）

> 交付目标：对接 SDK（rent-alipay-sdk）+ Spring Boot 应用（rent-app），提供后端接口给前端基础测试。
> 本手册面向执行人：按顺序完成【环境准备 → 数据库初始化 → 配置 → 构建 → 启动 → 联调】。

## 1. 交付物清单

| 模块 | 位置 | 说明 |
|------|------|------|
| 对接SDK | `rent-alipay-sdk/` | 15个服务端OpenAPI封装、RSA2签名/验签、通用协议层 |
| 后端应用 | `rent-app/` | 订单主链路接口（商品/订单/签约/风控/支付/异步通知） |
| DDL | `docs/支付宝对接/scripts/car_subscription-DDL.sql` | 12张表建表语句 |
| 测试数据 | `docs/支付宝对接/scripts/test-data-goods.sql` | 商品+SKU示例 |
| 构建脚本 | `docs/支付宝对接/scripts/build.bat` | mvn 打包 |
| 启动脚本 | `docs/支付宝对接/scripts/start-app.bat` | java -jar 启动 |

## 2. 环境准备

- JDK 1.8、Maven 3.6+（需可访问中央仓库或已配私服镜像）、MySQL 8
- 支付宝侧前置条件（缺一不可，否则创单/签约会报网关错误）：
  1. 汽车订阅类目（CAR_SUBSCRIPTION）白名单已开通
  2. 应用已获取15个 openapi 权限（alipay.commerce.rent.* / alipay.trade.refund）
  3. 已完成商品提报（回填 out_item_id/out_sku_id 到本地商品表）
  4. 密钥：应用私钥/支付宝公钥（开放平台"接口加签方式"设置为公钥模式）
  5. 异步通知地址必须公网可达（内网联调可用内网穿透）

## 3. 执行步骤

### 3.1 建库与初始化（依次执行）

```sql
CREATE DATABASE IF NOT EXISTS `car_subscription` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

```bat
mysql -uroot -p car_subscription < docs\支付宝对接\scripts\car_subscription-DDL.sql
mysql -uroot -p car_subscription < docs\支付宝对接\scripts\test-data-goods.sql
```

### 3.2 填写配置

编辑 `rent-app/src/main/resources/application.yml` 的 `alipay.rent` 段：

| 配置项 | 说明 |
|--------|------|
| app-id | 应用APPID |
| app-private-key | 应用私钥（PKCS8，一行Base64，不含头尾标记） |
| alipay-public-key | 支付宝公钥（一行Base64） |
| trade-app-id | 交易应用APPID（与app-id相同时可留空） |
| freeze-notify-url | 预授权冻结通知地址，公网 `https://…/api/v1/callback/alipay/notify` |
| pay-notify-url | 支付结果通知地址，同上路径 |

> 数据源账号密码同文件 `spring.datasource` 段，按本机 MySQL 修改。

### 3.3 构建与启动

```bat
cd /d Z:\订阅

docs\支付宝对接\scripts\start-app.bat
```

启动成功标志：日志输出 `Tomcat started on port(s): 8080`。

## 3.4 SDK结构说明（v2）

- 请求入参：rent-alipay-sdk 的 model 包下强类型DTO，操作类型/状态等全部枚举化，序列化自动转snake_case且null字段不传
- 调用方式：alipayRentClient.orderXxx(请求DTO)，方法与15个openapi一一对应
- 响应：RentResponse<Map<String,Object>>，响应字段名常量见 BizFields

## 4. 接口清单（前端联调用）

统一响应：`{code, message, data, success, timestamp}`，成功码 `SY000000`。
金额均为字符串（元，2位小数）；ID 均为字符串。

| 编号 | 接口 | 路径 |
|------|------|------|
| A0101001 | 商品分页 | POST /api/v1/rent/goods/page |
| A0102001 | 创建订单 | POST /api/v1/rent/order/create |
| A0102002 | 订单分页 | POST /api/v1/rent/order/page |
| A0102003 | 订单详情 | POST /api/v1/rent/order/detail |
| A0102004 | 商家交车 | POST /api/v1/rent/order/fulfillment/send |
| A0102005 | 收货确认 | POST /api/v1/rent/order/fulfillment/receive |
| A0102006 | 订单完结 | POST /api/v1/rent/order/fulfillment/finish |
| A0102007 | 订单关闭 | POST /api/v1/rent/order/close |
| A0102008 | 修改租期 | POST /api/v1/rent/order/modify |
| A0102009 | 获取签约串 | POST /api/v1/rent/order/sign |
| A0103001 | 风险咨询 | POST /api/v1/rent/risk/consult |
| A0103002 | 审核结论 | POST /api/v1/rent/risk/audit |
| A0104001 | 订单支付 | POST /api/v1/rent/order/pay |
| — | 支付宝异步通知 | POST /api/v1/callback/alipay/notify |

入参/出参完整定义见 `agent-dev-workflow/artifacts/stage02-技术设计/REQ001-API-Definition.md`。

### 4.1 联调请求示例（curl）

```bat
REM 商品分页
curl -X POST http://localhost:8080/api/v1/rent/goods/page -H "Content-Type: application/json" -d "{\"pageNo\":1,\"pageSize\":10}"

REM 创建订单（outSkuId用测试数据SKU；正式联调须换已提报的SKU）
curl -X POST http://localhost:8080/api/v1/rent/order/create -H "Content-Type: application/json" -d "{\"openId\":\"测试买家openId\",\"goodsId\":\"1001\",\"skuId\":\"2001\",\"installments\":[{\"installmentNo\":1,\"installmentPrice\":\"300.00\",\"planPayTime\":\"2026-10-01 00:00:00\"}],\"receiverInfo\":{\"receiverName\":\"张三\",\"receiverTel\":\"13800000000\",\"detailedAddress\":\"测试地址\"}}"

REM 订单详情
curl -X POST http://localhost:8080/api/v1/rent/order/detail -H "Content-Type: application/json" -d "{\"outOrderId\":\"创单返回的outOrderId\"}"
```

### 4.2 建议联调顺序（对应需求14步骤主链路）

商品分页 → 创单（A0102001）→ 风险咨询（A0103001）→ 审核结论-通过（A0103002）
→ 获取签约串（A0102009，前端唤起受理台完成免押冻结）→ 等待冻结通知（SIGNED）
→ 商家交车（A0102004）→ 收货确认（A0102005）→ 订单支付（A0104001，前端my.tradePay）
→ 等待支付通知 → 订单完结（A0102006）。
