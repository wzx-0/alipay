# 编码规范

## 编码体系

**业务领域编号**和**各业务领域的模块编号**需提前在 `业务领域清单` 中维护，编码生成前请先查阅该文件。

业务领域编号统一为2位（如 `01`、`02`）。

| 编码类型 | 前缀 | 格式 | 示例 | 校验正则 |
|---------|-----|------|------|---------|
| 数据字典 | `D` | `D{业务领域2位}{序号3位}` | D01001 | `^D\d{5}$` |
| 影像模板 | `F` | `F{业务领域2位}{序号3位}` | F01001 | `^F\d{5}$` |
| 影像类别 | `IC` | `IC{业务领域2位}{序号3位}` | IC01001 | `^IC\d{5}$` |
| 流程模板 | `P` | `P{业务领域2位}{序号3位}` | P02001 | `^P\d{5}$` |
| 流程节点 | 类型简称 | `{类型2位}{序号2位}` | UT01 | `^(UT\|WT\|ST)\d{2}$` |
| 业务异常码 | 纯数字 | `{业务领域2位}{模块2位}{序号3位}` | 0101001 | `^\d{7}$` |

### 流程节点类型

| 类型简称 | 节点类型 | 说明 |
|---------|---------|------|
| `UT` | usertask | 人工任务节点 |
| `WT` | receivetask | 等待任务节点 |
| `ST` | servicetask | 自动任务节点 |

> 流程节点序号按流程维度独立编号，每个流程内的节点序号从 `01` 开始递增。

## 使用流程

1. **确认业务领域**：询问用户或根据上下文确定业务领域编号（2位）
2. **确定类型**：判断需要生成哪种类型的编码
3. **确认已有编码**：查阅该业务领域下该类型已有的编码，确定序号起始值
4. **生成编码**：按对应格式生成新编码（序号 = 已有最大序号 + 1，从 01 开始）
5. **校验**：用编码体系表格中的正则校验生成的编码格式
6. **输出文档**：生成 `业务编码清单-{需求编号}-{需求名称}.md`，包含本次需求涉及的所有编码定义

## 输出文档格式

文件命名：`编码清单-{需求编号}-{需求名称}.md`，内容结构：

```markdown
# 编码清单 - {需求编号} - {需求名称}

## 数据字典

### D{编号}-{字典描述}

| 小类标识 | 小类描述 |
|---------|---------|
| 01 | 描述 |

## 影像类别

| 编码 | 描述 |
|-----|------|

## 影像模板

| 编码 | 描述 |
|-----|------|

## 流程模板

| 编码 | 描述 |
|-----|------|

## 流程节点

| 编码 | 节点类型 | 描述 |
|-----|---------|------|

## 业务异常码

| 异常码 | 描述 |
|-------|------|
```

> 按需包含本次涉及的编码类型，不涉及的类型无需输出空表。

> 数据字典每个字典一个独立表格，标题格式 `D{编号}-{字典描述}`，小类标识从 `01` 开始。枚举字段使用标识值存储，不使用描述文本。

## 数据字典规范（特有）

### 编码规则

- 小类标识从 `01` 开始，最多 `999`，每个字典内部独立编号
- 多值枚举：枚举值为小类标识（如 `01`、`02`），适用于状态、类型等
- 两面性枚举：枚举值为 `'0'`/`'1'`，适用于是/否、启用/禁用等，统一 `1` 正面、`0` 反面

---

## 通用规则

1. **编码唯一**：同一业务领域内编码不可重复
2. **编码不可变**：一旦生成不可修改，废弃编码标记 `DEPRECATED` 且不可复用
3. **命名规范**：大写字母 + 数字，无分隔符，固定位数
4. **编码使用**：数据库存储编码值，前端通过编码查询描述文本

### 常见错误

| 错误 | 正确做法 |
|-----|---------|
| 编码位数不对（`F0101`） | 严格按格式填充（`F01001`） |
| 序号从0开始 | 从 `01` 开始 |
| 复用已废弃编码 | 创建新编码 |
| 业务领域位数错误 | 领域统一2位 |
|                         |                            |
