# 测试范围

本文件用于确定应该为哪些代码生成测试。

## 范围确定

待生成测试的文件范围由调用方指定（git diff、文件列表或目录路径）。仅针对指定范围内的业务代码生成测试。

## 优先目标

### 1. Service 类

默认优先测试此类。

关注点：

- 业务规则
- 分支行为
- 状态流转
- 跨协作者的编排逻辑
- 异常抛出条件

### 2. 校验逻辑

在校验逻辑实现在以下位置时进行测试：

- Service 方法
- Controller 适配逻辑
- 自定义校验器
- 带有业务约束的转换器或组装器逻辑

关注点：

- 必填字段
- 非法状态流转
- 重复数据校验
- 不支持的枚举或编码值

### 3. 枚举与常量相关逻辑

仅在业务逻辑依赖以下内容时测试：

- 枚举转换
- 编码到含义的映射
- 默认值选择
- 基于常量或状态值的规则分支

不要仅为静态常量声明本身创建测试。

### 4. Repository 或 Mapper 层

仅在项目已有该层直接测试惯例时才测试。

示例：

- 已有 Mapper 测试先例
- Repository 包含值得断言的自定义查询行为
- 持久化适配器包含业务映射逻辑

如果项目没有直接测试该层，优先通过 Service 测试覆盖行为。

## 通常低价值

默认跳过，除非项目本身将其视为重要内容：

- 普通 DTO/VO 的 getter 和 setter
- 简单的 Controller 透传方法
- 无自定义逻辑的框架注解
- 简单的 Entity 字段声明

## Controller 测试

仅在 Controller 包含实质性逻辑时才创建 Controller 测试，例如：

- 请求参数适配
- 自定义校验分支
- 响应映射分支
- 异常转换

如果 Controller 方法只是委托给 Service 方法，通常 Service 测试就足够了。

## 最小目标规则

时间或上下文受限时，优先保障：

1. 该业务功能的核心 Service
2. 风险最高的规则分支
3. 最常见的非法输入路径
