# API 交互图规范

## 概述

API 交互图使用 Mermaid 时序图详细描述前端与服务端的交互流程。本文档规范了图的结构、语法和内容要求，确保输出一致、可读、可维护。

## 文件命名

- **单文件**：`api-interactions/需求编号-API-交互.mmd`
- **多文件拆分**：`api-interactions/需求编号-API-模块名-交互.mmd`

示例：
- `api-interactions/REQ-001-API-交互.mmd`（单文件）
- `api-interactions/REQ-001-API-列表查询-交互.mmd`（拆分为查询模块）
- `api-interactions/REQ-001-API-审批流程-交互.mmd`（拆分为审批模块）

## 文件格式

**.mmd 文件只包含纯 Mermaid 代码**，禁止包含 markdown 语法（如 `#`、`|`、`###` 等）。

如需说明文档，另建同名 `.md` 文件存放表格、参与者说明等内容。

## 语法要求

使用标准 Mermaid 时序图语法。核心规则如下：

| 规则 | 说明 |
|------|------|
| 参与者 | 使用缩写 + `as` + 中文说明，如 `participant P as 列表页` |
| 请求 | 使用 `->>`（实线箭头） |
| 返回 | 使用 `-->>`（虚线箭头） |
| 激活/停用 | 每个 `activate` 必须有对应的 `deactivate` |
| 条件分支 | `alt/else/end`、`opt/end`、`loop/end` 必须闭合 |
| 嵌套限制 | **`alt` 块内禁止嵌套 `alt`**，嵌套条件使用 `opt` |
| 自调用限制 | **禁止 `A->>A:` 形式的自调用**，服务端内部逻辑用 `Note` 标注，详细流程见 API 逻辑图 |

## 内容要求

### 描述范围

1. **仅描述前端 ↔ 服务端交互**
   - 不涉及中间件（DB、Redis、MQ、第三方服务等）
   - **不画服务端内部逻辑**（如"查询数据库"、"校验密码"等），这些属于 API 逻辑图范畴
   - 服务端内部处理用 `Note` 简述，详细流程见 API 逻辑图

2. **默认属于同一服务**
   - 没有特别指明时，所有 API 调用都属于同一个后端服务
   - 参与者通常为：用户（U）、前端页面/组件（P/F/D 等）、服务端（S）

### 参与者定义

1. **前端必须明确端类型**
   - 在交互图中，前端参与者需要明确标注所属端类型，使用后缀区分：
     - `H5`：移动端 H5 页面，如 `participant P_H5 as 订单H5页`
     - `APP`：原生 APP 页面，如 `participant P_APP as 订单APP页`
     - `WX`：微信公众号页面，如 `participant P_WX as 订单公众号页`
     - `PC`：PC 端页面，如 `participant P_PC as 订单PC页`
   - 示例：`participant P_H5 as 商品列表H5页`、`participant P_PC as 商品管理PC页`

2. **用户与前端的关系**
   - 用户通过特定端的前端页面进行操作
   - 示例：`U->>P_H5: 点击商品卡片`、`U->>P_PC: 点击新增按钮`

### 交互细节

1. **必须包含具体页面、按钮操作**
   - 例如：`U->>P_PC: 点击新增按钮`，而不是模糊的 `用户操作`
   - 页面内部逻辑用自身消息表示：`P_H5->>P_H5: 表单校验`

2. **必须描述前端 UI 交互细节**
   - 点击按钮后的弹窗、对话框、确认提示等必须明确描述
   - 示例：
     - `P_PC->>P_PC: 弹出新增表单弹窗`
     - `P_PC->>P_PC: 显示"确认删除？"确认框`
     - `P_PC->>P_PC: 关闭弹窗`
   - 这些纯前端交互不涉及服务端，但需要完整呈现用户操作路径

3. **API 编号必须标注**
   - 格式：`API编号-简短说明`
   - 示例：`P->>S: [API-001] 获取列表数据`

4. **API 必须源自 API 定义文档**
   - 数量不能多，也不能少
   - 编号必须与 API 定义完全一致

### 文件组织

- **内容不多**：生成一个文件即可
- **内容过多**：自行拆分为多个文件
  - 每个文件必须保证**业务逻辑闭环**
  - 按功能模块拆分（如：查询模块、编辑模块、审批模块）

## 质量检查清单

在输出交互图前，逐项检查：

- [ ] Mermaid 时序图语法正确（以 `sequenceDiagram` 开头，参与者、箭头、激活/停用、条件分支都正确）
- [ ] **嵌套限制**：`alt` 块内使用 `opt` 嵌套（禁止 `alt` 内嵌套 `alt`）
- [ ] **无自调用**：不使用 `A->>A:` 形式，服务端内部逻辑用 `Note`
- [ ] 前端参与者明确标注端类型（H5/APP/WX/PC）
- [ ] 包含具体页面、按钮操作（不是模糊的"用户操作"）
- [ ] 包含前端 UI 交互细节（弹窗、确认框、关闭弹窗等）
- [ ] API 编号与 API 定义文档完全一致（不多不少）
- [ ] 不涉及中间件（DB、Redis、MQ 等）
- [ ] 业务逻辑闭环完整（有始有终，操作有响应）
