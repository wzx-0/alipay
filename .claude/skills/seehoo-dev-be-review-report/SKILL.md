# 后端代码审查报告

## 职责

本 skill **只负责报告格式化输出**，不做审查判断。

## 输入

- 审查结果列表：每个问题包含文件路径、行号、所属维度（安全/性能/规范/简化）、严重等级（BLOCKER/MAJOR/MINOR/SUGGESTION）、问题描述、修复建议
- 审查范围信息：需求编号、日期、变更文件数

## 输出

一份 Markdown 审查报告，严格按下方模板输出，不增不减章节。

## 报告模板

```markdown
# 后端代码审查报告

> 需求编号：{需求编号}
> 审查日期：{日期}
> 审查范围：{文件数或变更说明}

## 问题清单

### 安全

| 文件 | 行号 | 等级 | 问题描述 | 修复建议 |
|------|------|------|----------|----------|

### 性能

| 文件 | 行号 | 等级 | 问题描述 | 修复建议 |
|------|------|------|----------|----------|

### 规范

| 文件 | 行号 | 等级 | 问题描述 | 修复建议 |
|------|------|------|----------|----------|

### 简化

| 文件 | 行号 | 等级 | 问题描述 | 修复建议 |
|------|------|------|----------|----------|

## 统计

| 维度 | BLOCKER | MAJOR | MINOR | 合计 |
|------|---------|-------|-------|------|
| 安全 | | | | |
| 性能 | | | | |
| 规范 | | | | |
| 简化 | | | | |
| **合计** | | | | |

## 结论

是否存在 BLOCKER：是 / 否
整体评价：{一段话，指出主要风险和修复优先级}
```

## 注意事项

- 某个维度下没有问题时保留空表格，不删除该维度章节
- 同一个问题不重复出现在多个维度中，按问题本质归入最相关的一个
