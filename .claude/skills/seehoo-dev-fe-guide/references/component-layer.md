# component-layer.md：组件层规范

## 组件分类与职责边界

### 三层分离

前端组件按职责分为三层，各层边界不可混淆：

| 层级 | 职责 | 特征 |
|------|------|------|
| **UI 组件** | 可复用的原子级交互组件（按钮、输入框、表格、弹窗壳等） | 无业务逻辑，纯 props 驱动，可跨模块复用 |
| **View 组件** | 业务功能点的交互组件（业务表单、业务表格、业务弹窗等） | 包含业务逻辑（校验、格式化、状态判断），与特定业务功能绑定 |
| **Page 组件** | 页面容器，组装 View 和 UI 组件 | 不含业务逻辑，负责布局和组件编排 |

### 职责原则

- UI 组件不引用 Store，不调用 API
- View 组件可引用 Store（通过 props/inject 传入），可调用 API 封装函数（独立弹窗等特殊场景）
- Page 组件不包含业务逻辑，只做布局编排

## 交互组件规范

### 表单组件

- 表单字段与 FRD-前端中的表单字段清单对齐，不得增减字段
- 表单校验规则遵循骨架已有的校验方案（如骨架 UI 库的表单验证规则）
- 表单提交调用对应的 API 封装函数
- 业务编码清单中的枚举字段，使用对应的枚举常量渲染选项列表

### 表格组件

- 表格列与 FRD-前端中的表格列清单对齐，不得增减列
- 表格数据源通过 props 或 Store 获取
- 表格操作列（编辑、删除等）通过事件回调通知父组件，不直接调用 API

### 弹窗组件

- 弹窗壳使用骨架 UI 库的 Dialog/Modal 组件
- 弹窗内容为 View 级组件（业务表单、详情展示等）
- 弹窗开关状态由父组件控制（visible prop + close 事件）

### Props 设计原则

- Props 命名语义化，以骨架 UI 库的 props 风格为准
- Props 类型声明使用 TypeScript，避免使用 any
- 事件命名遵循骨架既定事件风格（如 onXxx 或 handleXxx）

## 样式规范

### 原则

- 样式方案与骨架现有方案一致（CSS Modules / Scoped CSS / Tailwind / 等）
- 不引入骨架未使用的样式方案
- 业务组件样式写在组件文件内（跟随骨架既定样式组织方式）
- 全局样式修改需谨慎，仅限于骨架已有全局样式约定的范围内
