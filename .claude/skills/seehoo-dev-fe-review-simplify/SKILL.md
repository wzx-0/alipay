# Seehoo 前端简化审查

## 目标

识别并报告指定前端代码中不必要的复杂、重复或过度设计的代码。

本 skill 只产出审查报告，**不修复代码**。

## 调用方必须提供

- **待审查文件范围**：git diff 命令、文件列表，或目录路径
- **输出目录**：审查报告写入的目标目录

## 严重等级

| 等级 | 含义 |
|------|------|
| BLOCKER | 交付前必须修复 |
| MAJOR | 强烈建议修复 |
| MINOR | 建议修复 |
| SUGGESTION | 可选优化 |

## 执行工作流

### 第一步 — 确定待审查文件

按调用方指定的方式确定文件范围。只保留业务层文件（Views、Components、Stores、API 封装、Composables），排除测试类、静态资源、配置文件。

### 第二步 — 读取文件

完整读取第一步确定的每个文件。对于可能较长或较复杂的组件，用 Grep 检查其调用方，了解影响范围。

### 第三步 — 执行简化检查清单

对每个文件逐项检查以下清单，记录每个发现的精确文件路径和行号。

### 第四步 — 输出报告

按照下方格式，将报告写入调用方指定的输出目录。

## 简化检查清单

- [ ] **重复逻辑**：相同或高度相似的逻辑块/模板片段在被审查文件中出现 2 次及以上
- [ ] **死代码**：未使用的变量、Props、Emits、方法或导入（Grep 验证无引用）
- [ ] **组件过长**：单个 SFC 文件 `<script>` 部分超过 200 行（不含模板和样式）
- [ ] **嵌套过深**：模板中 `v-if` / `v-for` / `v-else` 嵌套超过 3 层
- [ ] **过度抽象**：Composable 或工具函数只在一处被使用，且逻辑简单（<10 行）
- [ ] **不必要的中间变量**：变量赋值后立即使用一次，对可读性无任何提升
- [ ] **冗余响应式声明**：声明了 `ref`/`reactive` 但从未被修改（应改为普通 `const`）
- [ ] **模板内联样式**：样式写在 `:style` 内联对象中而非 `<style>` 标签内
- [ ] **未拆分大组件**：单个组件同时承担数据获取、表单校验、弹窗管理、状态管理等多项职责（>3 种职责）

## 输出格式

**文件命名**：`{需求编号}-简化-审查报告.md`

```
# 简化审查报告

## 1. 审查范围
- 基准分支/文件来源：（由调用方说明）
- 变更文件数：N
- 文件列表：（逐行列出）

## 2. 问题清单

| 编号 | 文件 | 行号 | 等级 | 问题描述 | 修复建议 |
|------|------|------|------|----------|----------|

## 3. 统计

| 等级 | 数量 |
|------|------|
| BLOCKER | 0 |
| MAJOR | 0 |
| MINOR | 0 |
| SUGGESTION | 0 |

## 4. 结论

是否存在 BLOCKER：是 / 否
整体评价：（一段话）
```

## 边界说明

- 只审查调用方指定范围内的文件。
- 不重写或修复任何代码，只报告问题。
- 不重复安全、性能、规范审查的发现。
- 简化问题聚焦于结构和复杂度，不涉及正确性或安全性。

## 停止条件

遇到以下情况，停止执行并向调用方报告，不要自行猜测：

- 指定范围内没有 Vue/TS/JS 文件
- 代码库没有 git 历史记录（非 git 仓库，但调用方要求 git diff）
- 某个文件因访问或编码问题无法读取
