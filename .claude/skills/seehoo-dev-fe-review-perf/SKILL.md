# Seehoo 前端性能审查

## 目标

识别并报告指定前端代码中的性能风险，对齐 seehoo-dev-fe-guide 性能规则。

本 skill 只产出审查报告，**不修复代码**。

## 调用方必须提供

- **待审查文件范围**：git diff 命令、文件列表，或目录路径
- **API 交互时序图路径**：用于核查请求并发与数据加载顺序（可选，缺失时跳过并发优化检查并在报告中注明）
- **输出目录**：审查报告写入的目标目录

## 严重等级

| 等级 | 含义 |
|------|------|
| BLOCKER | 交付前必须修复 |
| MAJOR | 强烈建议修复 |
| MINOR | 建议修复 |
| SUGGESTION | 可选优化 |

导致首屏白屏或明显卡顿的发现，通常定为 BLOCKER 或 MAJOR。

## 执行工作流

### 第一步 — 确定待审查文件

按调用方指定的方式确定文件范围。只保留业务层文件（Views、Components、Stores、API 封装、路由配置），排除测试类、静态资源、配置文件。

### 第二步 — 读取文件与参考文档

1. 完整读取每个待审查的业务层文件。
2. 若调用方提供了 API 交互时序图，读取以评估请求时序与并发合理性。

### 第三步 — 执行性能检查清单

对每个文件逐项检查以下清单，记录每个发现的精确文件路径和行号。

### 第四步 — 输出报告

按照下方格式，将报告写入调用方指定的输出目录。

## 性能检查清单

### 渲染效率
- [ ] **不必要的重渲染**：`ref`/`reactive` 更新不触发无关组件渲染；列表项使用 `:key` 且值稳定（Grep：`:key="index"` 在列表中属反模式）
- [ ] **计算属性滥用**：复杂计算已用 `computed` 缓存，不在模板中直接写复杂表达式
- [ ] **Watch 滥用**：`watch` 不监听整个 `reactive` 对象，使用具体属性或 `computed` 替代

### 资源加载
- [ ] **路由懒加载**：非首屏路由组件使用 `() => import(...)` 懒加载（Grep 路由配置中的 `component:` 是否为函数式 import）
- [ ] **组件按需加载**：大型第三方组件（如 ECharts、富文本编辑器）按需引入，不全局注册
- [ ] **图片优化**：图片使用合适格式（WebP/AVIF），大图有占位符或渐进加载

### 内存安全
- [ ] **事件监听未清理**：`addEventListener`、`setTimeout`、`setInterval` 在 `onUnmounted` 中清理（Grep：`addEventListener` 确认有对应 `removeEventListener`）
- [ ] **大列表优化**：数据量 >100 条的列表使用虚拟滚动或分页
- [ ] **闭包引用未释放**：长生命周期对象不持有大对象引用

### API 请求
- [ ] **重复请求**：相同请求未并发发出多次（如未做防抖/取消上次请求）
- [ ] **请求时机**：数据请求不在 `onBeforeMount` 中执行（影响 SSR），在 `onMounted` 或路由守卫中执行
- [ ] **数据量控制**：列表 API 有分页参数，未一次性加载全部数据

## 边界说明

- 只审查调用方指定范围内的文件。
- 不重写或修复任何代码，只报告问题。
- 不重复简化、安全、规范审查的发现。
- 性能问题聚焦于运行时效率，不涉及代码风格或安全性。

## 停止条件

遇到以下情况，停止执行并向调用方报告，不要自行猜测：

- 指定范围内没有 Vue/TS/JS 文件
- 代码库没有 git 历史记录（非 git 仓库，但调用方要求 git diff）
