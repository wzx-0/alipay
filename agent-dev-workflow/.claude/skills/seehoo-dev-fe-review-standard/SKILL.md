# Seehoo 前端规范审查

## 目标

验证指定前端代码是否符合 seehoo-dev-fe-guide 规范及项目业务编码清单。

本 skill 只产出审查报告，**不修复代码**。

## 调用方必须提供

- **待审查文件范围**：git diff 命令、文件列表，或目录路径
- **业务编码清单路径**：用于核查枚举值与常量是否与清单一致（可选，缺失时跳过业务编码对齐检查并在报告中注明）
- **输出目录**：审查报告写入的目标目录

## 严重等级

| 等级 | 含义 |
|------|------|
| BLOCKER | 交付前必须修复 |
| MAJOR | 强烈建议修复 |
| MINOR | 建议修复 |
| SUGGESTION | 可选优化 |

## 执行工作流

### 第一步 — 确定待审查文件

按调用方指定的方式确定文件范围。只保留业务层文件（Views、Components、Stores、API 封装、路由配置、类型声明），排除测试类、静态资源、配置文件。

### 第二步 — 加载规范与参考文档

1. **调用 `seehoo-dev-fe-guide` skill**，按代码审查模式加载规范（guide 内部会指示加载哪些 references）。
2. 完整读取每个待审查的业务层文件。
3. 若调用方提供了业务编码清单，读取以备第三步核查。

### 第三步 — 执行规范核查

对每个文件，以 seehoo-dev-fe-guide 全量规范为标准逐项核查，记录每个发现的精确文件路径和行号。

此外，单独核查以下项（guide 未覆盖）：

**业务编码对齐**（业务编码清单缺失时跳过）
- [ ] 代码中每个状态值、类型码在业务编码清单中有对应条目
- [ ] 组件内无硬编码的业务状态字符串/数字（Grep 检查魔法值）

**TypeScript 规范**
- [ ] 无 `any` 类型使用（Grep：`: any` 或 `as any`）
- [ ] Props 使用接口声明（`defineProps<T>()`），非运行时声明
- [ ] 导出函数/组件有 JSDoc 注释

**Vue 3 规范**
- [ ] 使用 `<script setup lang="ts">`，非 Options API
- [ ] 响应式对象使用正确的 API（`ref` vs `reactive`）
- [ ] 事件监听在 `onUnmounted` 中清理

### 第四步 — 输出报告

按照下方格式，将报告写入调用方指定的输出目录。

## 输出格式

**文件命名**：`{需求编号}-规范-审查报告.md`

```
# 规范审查报告

## 1. 审查范围
- 基准分支/文件来源：（由调用方说明）
- 变更文件数：N
- 文件列表：（逐行列出）

## 2. 问题清单

| 编号 | 文件 | 行号 | 等级 | 规范类别 | 问题描述 | 修复建议 |
|------|------|------|------|----------|----------|----------|

## 3. 统计

| 等级 | 数量 |
|------|------|
| BLOCKER | 0 |
| MAJOR | 0 |
| MINOR | 0 |
| SUGGESTION | 0 |

## 4. 结论

是否存在 BLOCKER：是 / 否
整体评价：（一段话）
```

## 边界说明

- 只审查调用方指定范围内的文件。
- 不重写或修复任何代码，只报告问题。
- 不重复简化、安全、性能审查的发现。
- 规范问题聚焦于命名、结构和编码约定，不涉及运行时行为或安全性。

## 停止条件

遇到以下情况，停止执行并向调用方报告，不要自行猜测：

- 指定范围内没有 Vue/TS/JS 文件
- 代码库没有 git 历史记录（非 git 仓库，但调用方要求 git diff）
- seehoo-dev-fe-guide 的 references 文件无法读取
