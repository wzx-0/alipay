# API 逻辑图参考

## 节点命名约定

| 节点类型 | 命名规则 | 示例 |
|---------|---------|------|
| 开始/结束 | Start/End | Start, End |
| 判断节点 | 英文/驼峰命名,表达判断条件 | Validate, NeedExtCall, DataSizeCheck |
| 处理节点 | 动作+对象 | QueryField, TxCommit, BuildResult |
| 异常节点 | 错误类型 | ParamError, BizError, TimeoutError |

### 节点 ID 唯一性

**重要**：每个节点 ID 在同一文件中必须唯一，不得重复定义。

| 错误示例 | 正确做法 |
|---------|---------|
| `DoCheck[处理]` 和 `DoCheck{判断?}` 同时存在 | 用不同 ID，如 `DoCheck[处理]` 和 `CheckResult{判断?}` |
| 同一 ID 定义两次 | 每个 ID 只定义一次 |

## 领域间调用标记格式

```
NodeID["调用：服务名-API编号|API名称"]
```

注意：节点文本包含 `|` 时必须用双引号包裹，否则 Mermaid 会将其误认为连接线标签。

示例:
```
CallExt["调用：订单服务-API001|创建订单API"]
CallUser["调用：用户服务-API010|查询用户信息API"]
```

## 设计要点

### 事务边界

- 事务应尽快提交，`TxBegin` 到 `TxCommit` 之间只保留必要的DB操作
- 事务内避免调用外部服务，跨服务调用应放在事务外
- 外部调用失败时需画补偿或回滚节点

### 异常边界

- 调用其他系统/内部服务接口时，需画异常处理节点和补偿节点
- 外部调用失败时需补偿或回滚已执行的DB操作

### 性能边界

- **禁止逐条处理**: 禁止出现逐条处理节点，需画批量处理节点（BatchQuery、BatchUpdate）
- **实时场景**: 耗时操作需标注同步/异步方式
  - 同步: 画顺序调用节点
  - 异步: 画 MQ/异步线程节点，并画失败补偿节点
- **批处理场景**: 大数据量处理需画分批/流式节点
  - 批量操作画 BatchUpdate/BatchInsert 节点
  - 大数据量查询画 StreamQuery/游标读取 节点

### 逻辑幂等

- 操作类场景需画幂等保障节点：
  - `IdempotentCheck` 幂等检查节点
  - `AcquireLock` 获取锁节点（分布式锁/数据库锁）
  - 或 `StatusCheck` 状态校验节点

## 子图(subgraph)使用规范

| 规则 | 说明 |
|------|------|
| 使用场景 | 单个API逻辑较复杂时，用子图将相关操作分组 |
| 子图命名 | 中文业务含义，如 `库存扣减事务`、`通知用户` |
| 子图边界 | 子图入口和出口必须连接到子图外的节点 |
| 子图内异常 | 子图内的错误节点也需连接到 End |
| 嵌套限制 | 不嵌套子图，最多一层 |

## 常见反模式

| 反模式 | 正确做法 |
|--------|---------|
| 事务内调用外部服务 | 外部调用放在事务外，失败时补偿回滚 |
| 循环内逐条DB操作 | 使用 `BatchInsert`/`BatchUpdate` 批量节点 |
| 只有成功路径，无失败分支 | 每个判断节点必须有失败分支流向 End |
| 异常节点未连接到结束 | 所有异常节点必须流向 End 节点 |
| 聚合类接口串行调用 | 无依赖的多个调用应并行，用分支节点表示 |
| 查询类接口不画缓存 | 查询类必须体现缓存策略节点 |
| 操作类接口不画幂等 | 操作类必须有幂等检查或状态校验 |
