# API 逻辑图设计规范

使用 Mermaid 流程图描述每个 API 的后端业务逻辑处理流程。

## 使用步骤

1. **先读规范** — 阅读 `references/api-rules.md`，了解节点命名、调用格式、设计要点和反模式
2. **识别类型** — 查询类、操作类、聚合类，选对应模板
3. **读对应模板** — 查询类读 `query-template.md`，操作类读 `operation-template.md`，聚合类读 `aggregate-template.md`
4. **创建文件** — 按命名规范为每个API建独立文件
5. **按模板绘制** — 模板已包含必含环节和节点命名约定，直接参照；复杂场景用子图分组，见 `references/subgraph-example.md`
6. **逐项检查** — 按检查清单确认无遗漏

## 文件命名

```
api-logics/需求编号-API编号-API名称-Logic.mmd
```

示例: `api-logics/PRJ-001-API003-创建订单-Logic.mmd`

## 文件格式

**.mmd 文件只包含纯 Mermaid 代码**，禁止包含 markdown 语法（如 `#`、`|`、`###` 等）。

如需说明文档，另建同名 `.md` 文件存放表格、事务边界说明等内容。

## 语法要求

- `flowchart TD` 开始，节点有有意义标识，无孤立节点
- `-->` 表流程，连接线加标签如 `|成功|`
- 复杂业务用 `subgraph` 分组（不嵌套）
- 领域间调用格式：`节点ID["调用：服务名-API编号|API名称"]`（引号不可省略）
- **节点 ID 唯一性**：每个节点 ID 在同一文件中必须唯一，不得重复定义

## 按类型选择模板

| 类型 | 典型场景 | 核心关注点 | 模板文件 |
|------|---------|-----------|---------|
| 查询类 | 列表/详情/统计 | 缓存策略、流式查询、权限过滤 | `query-template.md` |
| 操作类 | 创建/更新/删除 | 幂等、事务、字段生命周期、跨服务补偿 | `operation-template.md` |
| 聚合类 | 编排多服务数据 | 并行调用、降级策略、核心数据校验 | `aggregate-template.md` |

## 质量检查清单

### 必检（所有API）

- [ ] 语法正确可渲染，文件数与API数一致
- [ ] 含入参校验、DB操作、异常处理
- [ ] 流程完整无孤立节点，判断有失败分支
- [ ] 所有异常连 End，DB操作标明类型
- [ ] **节点 ID 唯一性**：同一节点 ID 不得重复定义

### 按类型

| 类型 | 检查项 |
|------|--------|
| 查询类 | 缓存策略节点、大数据量流式查询 |
| 操作类 | 幂等检查、事务边界、字段生命周期 |
| 聚合类 | 并行调用分支、降级策略、核心数据校验 |

### 跨服务及通用

- [ ] 调用按 `节点ID["调用：服务名-API编号|API名称"]` 标记（引号不可省略），有异常和补偿
- [ ] 事务内无外部服务调用
- [ ] 无逐条处理，已用批量/流式
- [ ] 实时/异步/批处理方式明确
