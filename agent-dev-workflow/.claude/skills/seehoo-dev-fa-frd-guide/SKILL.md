# FRD 自动生成技能

## 概述

本技能用于将PRD（产品需求文档）自动转化为FRD（功能需求文档），输出**前后端分离**的结构化技术需求文档。

### 核心原则

1. **完整覆盖PRD**：必须完全包含PRD中的全部逻辑内容，不遗漏任何业务规则、状态流转、权限要求、字段定义
2. **业务逻辑内聚**：同一业务操作的所有描述集中在一处，不分散
3. **业务逻辑有边界**：明确区分前端职责和后端职责
4. **结构化输出**：使用标准化模板，确保文档一致性

### FRD 定位

| FRD 管什么 | FRD 不管什么 |
|-----------|------------|
| ✅ 有哪些业务操作、前后端各管什么 | ❌ 具体 API 的入参出参定义 |
| ✅ 业务规则、状态流转、权限归属 | ❌ 字段类型、长度、格式 |
| ✅ 逻辑流（文字描述） | ❌ 数据库表结构、代码级实现细节 |
| ✅ 业务规则、状态流转、权限归属 | ❌ 数据库表结构 |
| ✅ 逻辑流（文字描述） | ❌ 代码级实现细节 |

## 输入要求

- **PRD文档路径**：产品需求文档的文件路径
- **需求编号**（可选）：用于文档命名，如 `20260306`
- **需求名称**（可选）：用于文档命名，如 `营业执照管理`

## 输出文档

### 文件命名

```
FRD-{需求编号}-{需求名称}-前端.md
FRD-{需求编号}-{需求名称}-后端.md
```

> 注：不强制按模块拆分，一个需求输出一个前端文档 + 一个后端文档。完整路径由调用此技能的 SOP 决定。

### 1. FRD-前端

#### 标准章节结构

| 章节 | 内容说明 | 必填 |
|------|---------|------|
| 文档头 | 来源PRD、生成日期、文档状态 | ✅ |
| 一、业务操作清单 | 每个业务操作的页面交互、校验、调用入口、前端职责边界 | ✅ |
| 二、待确认事项 | 需要产品/架构师确认的问题 | ✅ |

#### 文档头

```markdown
# FRD - {需求编号} - {需求名称} - 前端

| 来源PRD | 生成日期 | 文档版本 |
|---------|---------|---------|
| xxx.md  | 2026-xx-xx | v1.0 |
```

#### 一、业务操作清单

每个业务操作按以下结构描述：

##### 业务操作1：{操作名称}

**页面/组件**：
- 涉及哪些页面或组件

**交互逻辑**（文字描述）：
- 用户操作 → 前端处理 → 调用入口 → 响应处理
- 使用 `→` 连接步骤，明确用户操作和系统响应
- 包含条件分支（如：校验通过→...；校验失败→...）

**示例**：
```
点击【新增入库】→ 弹出表单 → 填写表单 → 点击保存 → 前端校验 →
  校验通过：调用营业执照入库接口 → 成功则刷新列表，提示"保存成功" →
  校验失败：字段下方红色提示错误信息
```

**前端校验规则**：

| 校验项 | 规则 | 适用场景 |
|--------|------|---------|
| 公司名称 | 必填，最大200字符 | 新增/编辑 |
| 营业执照编号 | 必填，格式校验 | 新增 |
| 附件 | ≤5份，仅 jpg/png/pdf | 新增/编辑 |

**前端职责边界**：
- 前端负责：XXX（如：表单展示、必填校验、附件格式校验、调用API）
- 后端负责：XXX（如：编号唯一性校验、业务规则校验、落库）

#### 二、待确认事项

| 序号 | 问题 | 需要谁确认 |
|------|------|----------|
| Q-FE-001 | 具体问题描述 | 产品/架构师 |

### 2. FRD-后端

#### 标准章节结构

| 章节 | 内容说明 | 必填 |
|------|---------|------|
| 文档头 | 来源PRD、生成日期、文档状态 | ✅ |
| 一、业务操作清单 | 每个业务操作的规则、状态、权限、外部依赖、后端职责边界 | ✅ |
| 二、待确认事项 | 需要确认的问题 | ✅ |

#### 文档头

```markdown
# FRD - {需求编号} - {需求名称} - 后端

| 来源PRD | 生成日期 | 文档版本 |
|---------|---------|---------|
| xxx.md  | 2026-xx-xx | v1.0 |
```

#### 一、业务操作清单

每个业务操作按以下结构描述：

##### 业务操作1：{操作名称}

**业务规则**：
- 规则1：XXX
- 规则2：XXX

**状态流转**：
- 无状态变更（新建直接落库）或
- 状态A → 状态B → 状态C
- 使用文字描述流转条件和触发操作

**权限控制**：
- 哪些角色可操作/查看

**外部依赖**：
- 依赖的外部系统及调用目的（如无则写"无"）

**后端逻辑流**（文字描述）：
- 请求入口 → 校验 → 处理 → 响应
- 包含条件分支和异常处理

**示例**：
```
调用营业执照入库接口 → 校验权限（档案管理员）→ 校验营业执照编号唯一性 →
  校验通过：落库 → 调用影像中心上传附件 → 返回成功 →
  校验失败：返回错误码和提示信息
```

**后端职责边界**：
- 前端负责：XXX
- 后端负责：XXX（如：编号唯一性校验、状态校验、落库、调用外部系统）

#### 二、待确认事项

| 序号 | 问题 | 需要谁确认 |
|------|------|----------|
| Q-BE-001 | 具体问题描述 | 产品/架构师 |

## 生成步骤

### Step 1：读取PRD

1. 读取PRD文档完整内容
2. 识别PRD中的业务模块（通常按章节划分）
3. 提取每个模块的：
   - 原型界面说明
   - 规则说明
   - 功能说明
   - 字段说明（筛选条件、列表字段、详情字段）

### Step 2：识别业务操作

1. **识别业务实体**：如"营业执照"、"借阅申请"
2. **识别业务操作**：如"入库"、"借阅"、"审批"、"归还"
3. **识别状态变更**：如"在库→借阅中→已归还"
4. **识别角色权限**：如"档案管理员"、"借阅人"
5. **识别外部依赖**：如"流程中心"、"影像中心"
6. **识别需要的接口**：从每个业务操作推导需要的前后端接口（接口名称、用途、请求方式，不含编号）

### Step 3：生成前端FRD

1. 从PRD原型界面提取页面/组件
2. 从功能说明和交互说明提取交互逻辑（文字描述）
3. 从字段说明提取前端校验规则
4. 明确每个操作的前端职责边界
5. 整理待确认事项

### Step 4：生成后端FRD

1. 从规则说明提取业务规则
2. 从状态变更推导状态流转
3. 从功能说明提取权限控制
4. 识别外部依赖系统
5. 编写后端逻辑流（文字描述）
6. 明确每个操作的后端职责边界
7. 整理待确认事项

### Step 5：输出文档

按照标准章节结构输出两个文档：
- `FRD-{需求编号}-{需求名称}-前端.md`
- `FRD-{需求编号}-{需求名称}-后端.md`

## 质量检查清单

生成FRD后，必须检查以下项目：

### 完整性检查
- [ ] 所有PRD业务操作都有对应的前后端描述
- [ ] 所有PRD规则都体现在后端业务规则中
- [ ] 所有PRD字段都有对应的前端校验或后端校验
- [ ] 所有状态变更都有状态流转描述
- [ ] 所有外部依赖都在后端FRD中列出

### 一致性检查
- [ ] 前端FRD调用的接口与后端FRD暴露的入口一一对应
- [ ] 业务操作的边界说明不矛盾

### 原则检查
- [ ] **业务逻辑内聚**：同一操作的描述集中在一处，不分散
- [ ] **边界清晰**：每个操作都明确了前端负责什么、后端负责什么

## 注意事项

1. **不遗漏PRD内容**：PRD中的所有业务逻辑都必须体现在FRD中
2. **逻辑流用文字描述**：不需要画流程图，用 `→` 连接步骤即可
3. **边界要明确**：每个业务操作都要说清楚前端管什么、后端管什么
4. **待确认事项要明确**：明确指出需要谁确认什么问题
5. **接口描述用名称**：FRD 中使用接口名称（如"营业执照入库接口"）描述调用关系，不含 API 编号；编号由 stage01 的 API 清单统一管理
