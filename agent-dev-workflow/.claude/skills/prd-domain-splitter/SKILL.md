# PRD 拆分技能

## ⚠️ 执行前必读

调用本 skill 前必须先读取 `constraints/execution-rules.md`，其规则优先级最高，与本文档冲突时以该文件为准。

## 核心原则

**只搬运重组，不改变内容**

1. ❌ 禁止脑补任何原始PRD中不存在的内容
2. ❌ 禁止跳过标题层级（`#`/`##`/`###` → L1/L2/L3）
3. ❌ 禁止为无详细描述的功能创建空文件

---

## 分层结构

| 层级 | 说明 | 示例 |
|-----|------|------|
| **L1 业务领域** | 顶层业务边界 | 产品中心、结算中心、订单中心 |
| **L2 子域** | 业务能力分组 | 提前还款、正常还款、费用计算 |
| **L3 功能点** | 最小业务逻辑单元（完整闭环） | 提前还款申请、审批、入账 |

---

## 执行流程（两阶段）

### 阶段一：生成业务领域清单（仅输出清单）

| 步骤 | 操作 |
|-----|------|
| 1 | 扫描PRD所有标题，建立章节索引表（层级、行号、内容行数） |
| 2 | 识别L1业务边界（按"XX中心/XX系统/XX模块"划分） |
| 3 | 划分L2子域（按业务能力分组） |
| 4 | 生成 `_业务领域清单.md`，内容包括：<br>- 纯文本树形结构展示L1/L2/L3层级<br>- 每个L1/L2分配两位数字编码（01, 02...）<br>- 每个L3标注内容行数、合并建议、最终文件名<br>- 无打勾框，末尾有清晰确认指引 |

### 阶段二：按确认的清单执行拆分

| 步骤 | 操作 |
|-----|------|
| 1 | 根据用户确认内容，确定L3合并/独立策略 |
| 2 | 提取L3功能点完整内容（不做任何改写） |
| 3 | 如需合并，用 `---` 分隔不同功能点 |
| 4 | 生成 `_待拆分清单.md` 和 `_章节处理对账表.md` |

---

## 文件命名规则

| 层级 | 命名格式 | 示例 |
|-----|---------|------|
| **L2功能文档** | `PRD-{L1编码}-{L2编码}-{L2名称}.md` | `PRD-01-01-项目管理.md` |
| **L3功能文档** | `PRD-{L1编码}-{L2编码}-{L2名称}-{L3名称}.md` | `PRD-01-01-项目管理-项目立项.md` |
| **L3合并文档** | 合并多个L3时，以L2功能命名 | `PRD-01-02-工时管理.md` |

---

## L3合并规则

| 场景 | 建议 |
|-----|------|
| 单个L3 < 50行 | ✅ 建议合并 |
| 同一业务流程的前后环节 | ✅ 建议合并 |
| 系统配置/参数设置 | ✅ 建议合并 |
| 单个L3 ≥ 100行，有完整业务闭环 | ❌ 不合并 |

---

## L3判定标准

**必须创建L3文件（满足任意一项）：**
- ✅ 原始PRD中有独立三级标题章节
- ✅ 有完整的CRUD操作描述
- ✅ 有完整业务流程（申请→审批→结果）
- ✅ 有具体页面字段定义 + 操作说明

**放入待拆分清单：**
- ⚠️ 只提到功能名称，无详细描述
- ⚠️ 缺少完整业务操作流程

---

## 输出文件清单

| 文件名 | 说明 |
|-------|------|
| `_业务领域清单.md` | 完整层级结构、编码分配、合并建议、确认指引 |
| `_待拆分清单.md` | 功能点名称 + 未拆分原因 + 精确行号范围 |
| `_章节处理对账表.md` | 所有三级标题的处理状态（已创建/待拆分/已合并） |
| `PRD-XX-XX-*.md` | L2/L3功能文档，按命名规则命名 |

## 验证清单

### 阶段一（清单生成）
- [ ] 已生成 `_业务领域清单.md`
- [ ] 纯文本树形结构展示所有层级
- [ ] 每个L1/L2都有两位数字编码
- [ ] 每个L3都标注了行数、合并建议、文件名
- [ ] 无打勾框，末尾有确认指引

### 阶段二（拆分完成）
- [ ] 所有内容100%来自原始PRD，无脑补
- [ ] 严格按标题层级拆分，无跳跃
- [ ] L3文件数 + 待拆分数 + 已合并数 = 三级标题总数
- [ ] 合并文件用 `---` 分隔功能点
- [ ] 合并后的文件 ≤ 10页
- [ ] 所有文件名符合命名规范
