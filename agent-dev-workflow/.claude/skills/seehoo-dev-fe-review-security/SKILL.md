# Seehoo 前端安全审查

## 目标

识别并报告指定前端代码中的安全漏洞，对齐 OWASP Top 10 与 seehoo-dev-fe-guide 安全规则。

本 skill 只产出审查报告，**不修复代码**。

## 调用方必须提供

- **待审查文件范围**：git diff 命令、文件列表，或目录路径
- **FRD-前端文档路径**：用于核查权限与角色规则（可选，缺失时跳过越权检查并在报告中注明）
- **输出目录**：审查报告写入的目标目录

## 严重等级

| 等级 | 含义 |
|------|------|
| BLOCKER | 交付前必须修复 |
| MAJOR | 强烈建议修复 |
| MINOR | 建议修复 |
| SUGGESTION | 可选优化 |

可能直接导致数据泄露或越权访问的发现，通常定为 BLOCKER 或 MAJOR。

## 执行工作流

### 第一步 — 确定待审查文件

按调用方指定的方式确定文件范围。只保留业务层文件（Views、Components、Stores、API 封装、路由配置），排除测试类、静态资源、配置文件。

### 第二步 — 读取文件与参考文档

1. 完整读取每个待审查的业务层文件。
2. 若调用方提供了 FRD-前端文档，读取以了解权限与角色要求。

### 第三步 — 执行安全检查清单

对每个文件逐项检查以下清单，必要时用 Grep 扫描特定模式。记录每个发现的精确文件路径和行号。

### 第四步 — 输出报告

按照下方格式，将报告写入调用方指定的输出目录。

## 安全检查清单

### A1 — XSS（跨站脚本）
- [ ] 没有使用 `v-html` 渲染不可信的用户输入或 API 返回值
- [ ] 使用 `v-html` 的场景已引入 DOMPurify 或等价净化库（Grep：`v-html` 后检查是否有 `sanitize`/`DOMPurify`）
- [ ] `location.hash`、`location.search` 等 URL 参数未直接插入 DOM 或模板

### A2 — CSRF 与 Token 安全
- [ ] Axios 拦截器正确附加了 Authorization Token
- [ ] Token 未使用 `localStorage` 存储敏感值（Grep：`localStorage.*token|localStorage.*Token`）
- [ ] 请求头包含 CSRF Token（如项目有要求）

### A3 — 敏感数据暴露
- [ ] 控制台日志未打印用户密码、Token、完整手机号、身份证号（Grep：`console\.(log|warn|info).*手机\|console\.*密码\|console\.*token`）
- [ ] 页面中敏感字段已做脱敏展示（手机号、证件号中间位替换）
- [ ] URL 参数不包含敏感信息（密码、Token）

### A4 — 权限控制缺失
- [ ] 需要权限的操作有 `v-permission` 或等价守卫（对照 FRD 中的权限规则，FRD 缺失时跳过此项）
- [ ] 路由配置中每个路由都有 `meta.permission` 定义
- [ ] 前端未硬编码完整权限逻辑（不替代后端校验）

### A5 — 输入校验
- [ ] 表单提交前有前端校验（必填、格式、长度）
- [ ] 文件上传限制了类型和大小
- [ ] 用户输入未经校验直接传给 API

## 输出格式

**文件命名**：`{需求编号}-安全-审查报告.md`

```

- 基准分支/文件来源：（由调用方说明）
- 变更文件数：N
- 文件列表：（逐行列出）

## 2. 问题清单

| 编号 | 文件 | 行号 | 等级 | OWASP类别 | 问题描述 | 修复建议 |
|------|------|------|------|-----------|----------|----------|

## 3. 统计

| 等级 | 数量 |
|------|------|

## 4. 结论
```

## 边界说明

- 只审查调用方指定范围内的文件。
- 不重写或修复任何代码，只报告问题。
- 不重复简化、性能、规范审查的发现。
- 安全问题聚焦于漏洞和数据安全，不涉及代码风格或性能。

## 停止条件

遇到以下情况，停止执行并向调用方报告，不要自行猜测：

- 指定范围内没有 Vue/TS/JS 文件
- 代码库没有 git 历史记录（非 git 仓库，但调用方要求 git diff）
