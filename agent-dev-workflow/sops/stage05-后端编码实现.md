## 🔄 执行过程

### Step0 - 初始化 TODO

- **输入**：无
- **产出**：`<TODO文件>` 中 stage05 区块（步骤进度表；子任务表在 Step3 开始前补充）
- **输出目录**：`<TODO文件>`

### Step1 - 前置检查

- **输入**：`<后端代码库根>` 当前状态、stage01/02 全部产物
- **产出**：前置检查结论（通过 / 阻塞项清单），写入 TODO
- **检查项**：
  1. `<后端代码库根>` 已存在可编译运行的项目骨架，**项目编译通过**
  2. 技术基座依赖齐全（按 `seehoo-dev-be-guide` 要求）
  3. 上游产物完整：FRD-后端、业务编码清单、DDL、API 定义、API 逻辑图、API 交互图均存在且互相一致
- **失败处理**：任一项不通过则阻塞，记入 TODO 异常并通知项目负责人；不替用户建骨架、不替用户改设计

### Step2 - 基础层落地

- **输入**：DDL、业务编码清单
- **产出**：Entity、Mapper/Repository、字典常量类、状态/类型枚举类、业务异常码定义
- **使用 Skill**：seehoo-dev-be-guide
- **输出目录**：`<后端代码库根>`
- **小验收**：项目编译通过

### Step3 - 按业务功能点实现 Service 层

- **输入**：对应业务功能点涉及的 API 定义、API 逻辑图、Step2 已落地的 Entity/Mapper/枚举/异常码（路径：`<后端代码库根>`）
- **产出**：Service、DTO/VO
- **使用 Skill**：seehoo-dev-be-guide
- **输出目录**：`<后端代码库根>`
- **小验收**：项目编译通过

### Step4 - 按业务功能点实现 Controller 层

- **输入**：对应业务功能点涉及的 API 定义、Step3 已落地的 Service/DTO/VO（路径：`<后端代码库根>`）
- **产出**：Controller、参数校验
- **使用 Skill**：seehoo-dev-be-guide
- **输出目录**：`<后端代码库根>`

### Step5 - 生成单元测试

## ⚠️ 本环节特殊约束

### 主 Agent 委派规则（防呆清单）

主 Agent 在委派任务时，**必须遵守以下规则**：

| 规则 | 说明 | 示例 |
|------|------|------|
| **不指定包路径/类名** | 由 backend-coding-expert 据 `seehoo-dev-be-guide` 与现有骨架决定 | ❌ "在 `com.seehoo.asset.license.controller` 下建 `LicenseController`"<br>✅ "实现「营业执照新增」业务功能点的 API" |

| **不指定测试实现细节** | 单元测试框架、测试类名、测试目录结构由子 Agent 据规范与骨架决定 | ❌ "用 JUnit5 写 `LicenseServiceTest` 并覆盖 8 个场景"<br>✅ "为本次实现代码生成对应的单元测试" |

### 设计偏差处理

- backend-coding-expert 在编码中如发现 FRD/API 定义/DDL 之间冲突或不可实现，**必须停止编码**，将偏差写入 TODO 异常栏，由主 Agent 通知项目负责人决定：
  - 微调可在本环节内修复——记录偏差、继续编码
  - 涉及设计变更——回退到 stage01 / stage02 修订，stage05 暂停
- 严禁子 Agent 自行"改设计以迁就实现"

### 环节执行约束

1. **顺序执行**：Step0 → Step6 不可跳步
2. **小验收强制**：Step2/3/4/5 的小验收命令必须实际执行，且小验收仅以"项目编译通过"为标准，不得以"应当能通过"代替
3. **异常记录**：所有编译失败、设计偏差均记入 TODO
4. **执行前检查**：每个 Step 执行前，必须先阅读本文件中该 Step 的完整规范（输入、产出、输出目录、小验收）
