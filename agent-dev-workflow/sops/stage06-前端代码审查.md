### Step1 - 安全审查

- **输入**：`<前端代码库根>` 业务源代码、FRD-前端、技术设计产物
- **产出**：安全审查报告
- **使用 Skill**：seehoo-dev-fe-review-security

### Step2 - 性能审查

- **输入**：`<前端代码库根>` 业务源代码、技术设计产物（API 定义、交互时序图）
- **产出**：性能审查报告
- **使用 Skill**：seehoo-dev-fe-review-perf
- **输出目录**：`<前端审查目录>`

### Step3 - 规范审查

- **输入**：`<前端代码库根>` 业务源代码、业务编码清单
- **产出**：规范审查报告
- **使用 Skill**：seehoo-dev-fe-review-standard
- **输出目录**：`<前端审查目录>`

### Step4 - 简化审查

- **输入**：`<前端代码库根>` 业务源代码
- **产出**：简化审查报告
- **使用 Skill**：seehoo-dev-fe-review-simplify
- **输出目录**：`<前端审查目录>`

### Step5 - 问题分流

- **输入**：Step1–Step4 产出的 4 份审查报告
- **产出**：问题分流结果（可在本阶段修复 / 需升级处理），写入 TODO stage06 区块
- **分流口径**：
  - **可在本阶段修复**：规范问题、局部安全问题、明显异常处理缺失、组件冗余/重复渲染、局部性能问题
  - **需升级处理**：涉及 FRD 变更、API 契约变化、路由/权限架构调整、全局状态管理重构等设计级问题
- **失败处理**：属于"需升级处理"的问题记入 TODO 异常并通知项目负责人；不得在本环节自行改设计

### Step6 - 人工确认

- **输入**：Step1–Step4 审查报告、Step5 问题分流结果、`<前端代码库根>` 业务源代码
- **产出**：人工确认结论
- **说明**：
    1. 主 Agent 完成 Step5 后，**主动列出 4 份审查报告摘要 + 问题分流清单**，等待人工回复
    2. 回复格式：【OK】确认通过，或提出调整要求
    3. 主 Agent 收到【OK】后，将分流结果写入 TODO，进入 Step7；若需调整，重新执行 Step5 或对应审查步骤
    4. 确认完毕，本步骤完成

### Step7 - 代码修复与交付

- **输入**：Step6 人工确认后的可修复问题清单、`<前端代码库根>` 业务源代码、相关设计产物
- **产出**：
  - 修复后的代码
  - 修复变更摘要（写入 TODO stage06 区块）：逐条列出改动的组件/文件名称及修复意图
- **使用 Skill**：seehoo-dev-fe-guide
- **输出目录**：`<前端代码库根>`
- **小验收**：项目编译通过
- **暂存代码**：执行 `git add <前端代码库根>`

## ⚠️ 本环节特殊约束

### 主 Agent 委派规则（防呆清单）

| 规则 | 说明 | 示例 |
|------|------|------|
| **不指定审查角度** | 具体审查项、检查清单由 skill 决定 | ❌ "重点审查 XSS 与越权访问"<br>✅ "对该需求源代码执行安全审查" |
| **不指定问题分级口径** | 严重等级、阻塞与否由 skill 决定 | ❌ "凡未处理异步错误直接判 critical"<br>✅ 由 skill 规范判定 |
| **不指定修复实现细节** | 修复方案由 frontend-coding-expert 据 `seehoo-dev-fe-guide` 与现有骨架决定 | ❌ "把这个组件拆成 3 个子组件并加防抖"<br>✅ "修复该审查报告指出的可落地问题" |
| **不扩大修复范围** | 只传递可修复问题清单与相关代码，不夹带新功能开发要求 | ❌ "顺手把列表导出也补上"<br>✅ "修复本阶段范围内的问题" |
| **审查完整传递 3 要素** | 必须包含：skill 名称、输入来源、输出目录 | 见上方模板 |
| **修复完整传递 4 要素** | 必须包含：skill 名称、输入来源、输出目录、小验收命令 | 见上方模板 |

### 环节执行约束

1. **执行顺序**：Step0 → Step7 顺序执行，不可跳步
2. **等待确认**：每个 Step 完成后等待【OK】
3. **小验收强制**：Step7 的小验收命令必须实际执行，不得以"应当能通过"代替
4. **异常记录**：所有审查执行异常、编译失败、设计级阻塞项均记入 TODO
5. **执行前检查**：每个 Step 执行前，必须先阅读本文件中该 Step 的完整规范（输入、产出、输出目录）
6. **人工确认门禁**：Step6 必须等待用户【OK】确认后，方可进入 Step7 代码修复；不得由子Agent自动跳过
