- **单元测试代码**：`<后端代码库根>`（与业务代码同库）
- **修复变更摘要**：`<TODO文件>` 中修复变更摘要区块

## 📤 输出目录

- **开发测试报告**：`<开发测试目录>`
- **stage08 完成记录**：作为段落写入 `<TODO文件>` 的 stage08 区块

## 🔄 执行过程

### Step0 - 初始化 TODO

- **输入**：`<TODO文件>` 中修复变更摘要区块
- **产出**：`<TODO文件>` 中 stage08 区块（步骤进度表 + 子任务表）
- **输出目录**：`<TODO文件>`

### Step1 - 前置检查

- **输入**：`<后端代码库根>` 、`<TODO文件>` 中修复变更摘要区块
- **产出**：前置检查结论（通过 / 阻塞项清单），写入 TODO
- **检查项**：
  1. `<后端代码库根>` 项目可编译
  2. 测试命令可执行
  3. 单元测试代码已存在于 `<后端代码库根>`
  4. 修复变更摘要已写入 TODO 修复变更摘要区块
- **失败处理**：任一项不通过则阻塞，记入 TODO 异常并通知项目负责人

### Step2 - 对齐单元测试

- **目的**：修复变更影响了生产代码，已生成的单元测试中部分用例的期望值/mock/断言可能已过时。本步骤基于已知的修复变更，主动更新受影响的测试用例，确保 Step3 的失败只来自真实回归，而非测试预期过时。
- **输入**：`<TODO文件>` 中修复变更摘要区块、`<后端代码库根>` 中已生成的单元测试
- **产出**：与修复变更对齐的单元测试代码（更新已失效用例的期望值/mock/断言，补充修复引入的新场景）
- **使用 Skill**：seehoo-dev-be-unit-test
- **输出目录**：`<后端代码库根>`
- **小验收**：项目编译通过

### Step3 - 执行开发自测

- **输入**：全量代码、经 Step2 对齐后的单元测试代码
- **产出**：测试执行结果，写入 TODO
- **验收项**：
  1. 项目编译通过
  2. 项目可正常启动（无报错、端口正常监听）
  3. 单元测试全部通过
- **失败处理**：任一项不通过，记录异常并暂停本环节，通知项目负责人

### Step4 - 输出开发测试报告与交付

- **输入**：Step3 测试执行结果、`<TODO文件>` 中修复变更摘要区块及升级处理项
- **产出**：开发测试报告，内容包括：
  - 测试执行结果（通过 / 失败用例统计）
  - 遗留风险（问题分流中"需升级处理"的问题清单）
  - 交付结论
- **输出目录**：`<开发测试目录>`
- **暂存代码**：执行 `git add <后端代码库根>`

## ⚠️ 本环节特殊约束

### 主 Agent 委派规则（防呆清单）

| 规则 | 说明 | 示例 |
|------|------|------|
| **不指定测试实现细节** | 测试框架、测试类名、测试目录结构由子 Agent 据规范与骨架决定 | ❌ "用 JUnit5 新增 `LicenseControllerTest` 并覆盖 10 个场景"<br>✅ "对齐修复变更，更新受影响的单元测试" |
| **不扩大测试范围** | 只更新受修复影响的测试，不在 prompt 中夹带新功能测试要求 | ❌ "顺手把导出功能也测一下"<br>✅ "修正因本次修复而失效或缺失的测试用例" |
| **完整传递 4 要素** | 必须包含：skill 名称、输入来源、输出目录、小验收命令 | 见上方模板 |

### 环节执行约束

1. **顺序执行**：Step0 → Step4 不可跳步
2. **小验收强制**：Step2 的小验收命令必须实际执行，不得以"应当能通过"代替
3. **测试执行强制**：Step3 的测试命令必须实际执行，不得以"理论上应通过"代替
4. **失败归因原则**：Step3 出现失败即认定为真实回归（因为 Step2 已消除测试过时因素），必须停止并通知项目负责人，不得在本环节自行改代码
5. **异常记录**：所有编译失败、测试失败均记入 TODO
6. **执行前检查**：每个 Step 执行前，必须先阅读本文件中该 Step 的完整规范（输入、产出、输出目录、小验收 / 验收项）
