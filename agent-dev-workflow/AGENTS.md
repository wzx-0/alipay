# 开发阶段总览 (Development Phase Overview)

## 🔄 执行模式

### 全量模式（默认）
按顺序执行全部环节：stage01 → stage02 → stage03 → stage04 → stage05 → stage06 → stage07 → stage08 → stage09

### 单环节模式
执行指定环节，不依赖前后步骤。触发方式：用户明确指定环节编号。
- 示例：「执行 stage02」→ 仅执行技术设计，不检查 stage01 是否完成
- 跳过依赖检查，TODO 清单仅记录当前环节进度

## 👥 执行者约定

### 主 Agent

- **是谁**：与用户对话的编排者
- **职责**：读 SOP、决定何时委派子 Agent、把控阶段流转、收口异常
- **不做什么**：不亲自产出技术设计、代码、审查报告等专业产物——这些一律委派给子 Agent

### 子 Agent

- **是谁**：主 Agent 以新会话/新实例方式委派的专家
- **特点**：每次调用是冷启动，不带主 Agent 的对话上下文；必须靠 prompt 把输入来源、输出目录、所用规范交代清楚
- **职责**：按 prompt 完成单步专业产出，第一步先加载对应规范文件读取模板（不要凭记忆生成格式）
- **不做什么**：不做跨阶段决策、不修改其他 Step 的产物


## 🔄 TODO 清单通用规则

- **命名**：`需求编号-todo.md`，位于 `todos/` 目录
- **结构**：按环节分组，每个环节包含步骤进度表 + 子任务表（均为表格格式）
    - **步骤进度表**：含步骤、描述、进度、是否完成、异常情况
    - **子任务表**：每个步骤下的子任务（如需拆分，则仅按照业务功能点来拆分），含子任务名称、描述、状态
- **更新**：完成即标记 ✅，异常必须记录
- **跨环节传递**：上环节全部完成 ✅ 后，方可进入下一环节

## ⚠️ 全局约束

| 约束           | 全量模式                        | 单环节模式             |
| -------------- | ------------------------------- | ---------------------- |
| **顺序执行**   | stage01 → stage09 不可跳步      | 仅执行指定环节         |
| **依赖检查**   | 上环节 ✅ 后方可进入下一环节     | 跳过                   |
| **等待确认**   | 每步完成后等待【OK】            | 每步完成后等待【OK】   |
| **TODO 更新**  | 完整记录所有环节进度            | 仅记录当前环节进度     |
| **异常记录**   | 所有异常记入 TODO               | 所有异常记入 TODO      |
| **异常升级**   | 阻塞性异常通知项目负责人        | 同左                   |
| **执行前检查** | 阅读该环节 SOP 文件完整规范     | 同左                   |
